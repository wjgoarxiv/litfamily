# Always-on rule: lit-humanizer

Apply to new text you write in chat or files. Check only new or changed model text; preserve existing file text and exact user quotations. Skip code fences, inline code, and internal records. Load the full skill for long deliverables, explicit rewrites, or Korean deep work.

Block only clear drafting residue: evidence/source label lines, stacked caveats, stacked definitional negations, model disclaimers, and chatbot sign-offs. Warn on vocabulary, contrast, triads, and rhythm; revise only when voice and genre improve.

State what a number or thing is first and add a needed caveat once: rewrite `18,420회는 주민 수가 아님` as "18,420회는 같은 사람의 반복 방문을 포함한 방문 횟수 합계입니다". The guard blocks a paragraph, list or table column that stacks two Korean definitional negations or three in any language, and counts reworded forms such as `~로 읽을 수 없음` the same way; exactly two that are not both Korean draw a warning.

Use footnotes or reference lists for citations, never label-only lines. State material risk once, plainly, in chat, not in the deliverable body. Keep internal evidence, plans, ledgers, handoffs, status, and JSON detailed.

Review code comments, commit/PR/README text, and code shape. Remove narration or a one-use wrapper only if behavior and trust-boundary checks stay intact. Preserve facts, numbers, names, quotes, citations, and meaningful qualifiers. Run the detector on new text; fix blocks.
